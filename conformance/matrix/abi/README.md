# ABI matrix

The **aggregate & multi-return passing** member of the conformance
matrix family (`../README.md`). Coordinate-addressed:

    conformance/matrix/abi/<category>/<...>.bn   (+ .expected)

Generated by `conformance/gen-abi-matrix.py`.

## Categories & assertion

- **`multi-return/<type>/<arity>`** — a function returns an N-tuple; the caller
  binds all components (`a, b, c := f()`) and asserts each.
- **`struct-return/<shape>`** — a function returns a struct by value; the caller
  reads every field.
- **`struct-param/<shape>`** — a struct is passed by value via a **direct**
  call; the callee reads every field.
- **`iface-param/<shape>`** — the same struct passed by value as an
  **interface-method** argument (vtable dispatch).
- **`funcval-param/<shape>`** — the same struct passed by value through a
  **function-value** call (a lifted named func).
- **`iface-return/<shape>`** / **`funcval-return/<shape>`** — a struct returned
  **by value** through an interface-method dispatch / a function-value call (the
  result-side mirror of `*-param`).
- **`iface-multi-return/<type>/<arity>`** / **`funcval-multi-return/<type>/<arity>`**
  — an N-tuple returned through a dispatch / a function-value call.

The `iface-*` / `funcval-*` categories are the **call-shape** axis: the same
aggregate/tuple crosses the boundary through an *indirect* call, where the
byval/sret lowering can diverge from the direct-call path. The axis spans
both **sides** — `*-param` (argument) and `*-return` / `*-multi-return` (result):
a multi-return-dispatch defect shows only on the result side.

Assertion: **every field's value survives the call boundary** (a mis-packed
tuple/aggregate reads a wrong value, or a broken byval lowering crashes).
Shapes are chosen to hit the ABI edges — non-8-multiple sizes (`three-u32` =
12B), internal padding (`u16-int`), sub-word packing (`five-u8` = 5B), the
>16-byte memory-class threshold (`three-int` = 24B), and arities past the
in-register limit.

## Current state

No cell carries an `.xfail.<mode>` marker. The **result-side** cells
(`*-return` / `*-multi-return`) pin:

- **iface multi-return dispatch** — `iface-multi-return/*`: an interface method
  returning ≥2 values must dispatch with every component intact. A broken
  lowering fails differently per backend — an LLVM compile error (`extractvalue
  void`), silent wrong values or empty output on the natives, sub-word (`uint16`)
  components packed into one word on the VM — so the assertion must be
  value-correctness across the *full* backend set; a compile-only or VM-only check
  misses a native silent miscompile.
- **funcval multi-return destructure** — `funcval-multi-return/*`: `a, b := fv()`
  for `fv @func() (T, U)` must type-check, i.e. the front-end expands the
  func-value kinds' results, not only `TYP_FUNC`'s.
- **funcval sub-word struct-return** — `funcval-return/five-u8`: a 5×`uint8`
  struct returned through a function-value call (a facet of the `five-u8`
  packing family, separate from the `iface-return` and direct variants).

The **param-side** cells pin:

- a >16-byte struct (`three-int` = 24B) passed by value through an **indirect**
  call (`iface-param` / `funcval-param`): the indirect signature needs the same
  `byval` lowering as the direct `struct-param/three-int`, or the call crashes;
- struct param+return of `three-u32` (non-8-multiple) and `five-u8`
  (sub-word-packed), where a packing defect corrupts the trailing field — through
  every call shape, since it is the packing, not the call shape;
- sub-word (`uint16`) multi-return at arity ≥ 3, and all-int multi-return up to
  arity 5 (past the in-register limit).

## Planned

More call shapes (handle / `__c_call`) and more aggregate shapes (nested,
larger, managed-field). A 17-byte shape would pin the >16-byte memory-class
threshold exactly (the current shapes bracket it to (16, 24]).
