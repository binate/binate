# ABI matrix

The **aggregate & multi-return passing** (Class 4) member of the conformance
matrix family (`../README.md`). Coordinate-addressed:

    conformance/matrix/abi/<category>/<...>.bn   (+ .expected)

Generated by `conformance/gen-abi-matrix.py`.

## Categories & assertion

- **`multi-return/<type>/<arity>`** — a function returns an N-tuple; the caller
  binds all components (`a, b, c := f()`) and asserts each.
- **`struct-return/<shape>`** — a function returns a struct by value; the caller
  reads every field.
- **`struct-param/<shape>`** — a struct is passed by value via a **direct**
  call; the callee reads every field.
- **`iface-param/<shape>`** — the same struct passed by value as an
  **interface-method** argument (vtable dispatch).
- **`funcval-param/<shape>`** — the same struct passed by value through a
  **function-value** call (a lifted named func).

The last two are the **call-shape** axis: the same aggregate crosses the
boundary through an *indirect* call, where the byval/sret lowering can diverge
from the direct-call path (§3.9).

Assertion: **every field's value survives the call boundary** (a mis-packed
tuple/aggregate reads a wrong value, or a broken byval lowering crashes).
Shapes are chosen to hit the ABI edges — non-8-multiple sizes (`three-u32` =
12B), internal padding (`u16-int`), sub-word packing (`five-u8` = 5B), the
>16-byte memory-class threshold (`three-int` = 24B), and arities past the
in-register limit.

## Current state

The VM passes every cell. The other backends have CONFIRMED defects (xfailed +
filed `claude-todo.md` / §3.9):

- **LLVM — CRITICAL.** A >16-byte struct (`three-int` = 24B) passed by value
  through an **indirect** call (`iface-param` / `funcval-param`) **SIGSEGVs**.
  The *direct* `struct-param/three-int` is fine, so the indirect-call path
  lowers the byval aggregate incorrectly (wrong/missing `byval` on the indirect
  signature). Crashes on every LLVM execution mode (`builder-comp`,
  `-comp-comp`, `-comp-comp-comp`, and — by reasoning, CI-confirmed — the
  `arm32` modes). The VM and the native backends pass `three-int`.
- **aa64** — struct param+return of `three-u32` (non-8-multiple) and `five-u8`
  (sub-word-packed): the trailing field is corrupted. The same defect shows
  through `iface-param` / `funcval-param` (it is the packing, not the call
  shape).
- **x64** — sub-word (`uint16`) multi-return at arity ≥ 3, and struct **param**
  of `three-u32` / `five-u8` (struct-*return* works on x64); likewise visible
  through the indirect call shapes.

The x64 multi-return n=2-cap from the audit (§3.1) is **FIXED** — all-int
multi-return up to arity 5 passes everywhere.

## Planned

More call shapes (handle / `__c_call`) and more aggregate shapes (nested,
larger, managed-field). A 17-byte shape would pin the LLVM crash threshold
exactly (currently bracketed to (16, 24]).
