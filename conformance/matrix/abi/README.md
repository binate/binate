# ABI matrix

The **aggregate & multi-return passing** (Class 4) member of the conformance
matrix family (`../README.md`). Coordinate-addressed:

    conformance/matrix/abi/<category>/<...>.bn   (+ .expected)

Generated by `conformance/gen-abi-matrix.py`.

## Categories & assertion

- **`multi-return/<type>/<arity>`** — a function returns an N-tuple; the caller
  binds all components (`a, b, c := f()`) and asserts each.
- **`struct-return/<shape>`** — a function returns a struct by value; the caller
  reads every field.
- **`struct-param/<shape>`** — a struct is passed by value via a **direct**
  call; the callee reads every field.
- **`iface-param/<shape>`** — the same struct passed by value as an
  **interface-method** argument (vtable dispatch).
- **`funcval-param/<shape>`** — the same struct passed by value through a
  **function-value** call (a lifted named func).
- **`iface-return/<shape>`** / **`funcval-return/<shape>`** — a struct returned
  **by value** through an interface-method dispatch / a function-value call (the
  result-side mirror of `*-param`).
- **`iface-multi-return/<type>/<arity>`** / **`funcval-multi-return/<type>/<arity>`**
  — an N-tuple returned through a dispatch / a function-value call.

The `iface-*` / `funcval-*` categories are the **call-shape** axis: the same
aggregate/tuple crosses the boundary through an *indirect* call, where the
byval/sret lowering can diverge from the direct-call path (§3.9). The axis spans
both **sides** — `*-param` (argument) and `*-return` / `*-multi-return` (result).
The result side was the empty region that hid the multi-return-dispatch defect.

Assertion: **every field's value survives the call boundary** (a mis-packed
tuple/aggregate reads a wrong value, or a broken byval lowering crashes).
Shapes are chosen to hit the ABI edges — non-8-multiple sizes (`three-u32` =
12B), internal padding (`u16-int`), sub-word packing (`five-u8` = 5B), the
>16-byte memory-class threshold (`three-int` = 24B), and arities past the
in-register limit.

## Current state

The **param-side** cells are mostly green (only the arm32 `three-int` indirect
byval crash remains xfailed). The **result-side** cells (`*-return` /
`*-multi-return`) surfaced four distinct multi-return / sub-word defects — three
previously undocumented — all filed in `explorations/claude-todo.md` and xfailed:

- **iface multi-return dispatch (CRITICAL).** `iface-multi-return/*`: an
  interface method returning ≥2 values can't be dispatched. **LLVM** → compile
  error `extractvalue void`; **native aa64/x64** → **SILENT WRONG-CODE** (wrong
  values / empty output — not a crash); **VM** is correct for `int` but **wrong
  for `uint16`** (sub-word components packed into one word). So the assertion
  must be value-correctness across the *full* backend set — a compile-only or
  VM-only check misses the native silent miscompile.
- **funcval multi-return destructure (MAJOR).** `funcval-multi-return/*`:
  `a, b := fv()` for `fv @func() (T, U)` is rejected at **type-check**
  (`assignment count mismatch`) on every mode — the front-end only expands
  `TYP_FUNC`, not the func-value kinds.
- **native funcval sub-word struct-return (CRITICAL).** `funcval-return/five-u8`:
  a 5×`uint8` struct returned through a function-value call is mis-packed on
  native aa64/x64 (the `iface-return` and direct variants are fine — funcval-path
  specific; a facet of the native `five-u8` packing family).

(The arm32 result-side xfails are by analogy — no local qemu — so a few may be
stale-skips; the multi-return ones are high-confidence, `funcval-return/five-u8`
on arm32 is unverified.)

The remaining **param-side** defects below were CONFIRMED earlier (xfailed +
filed `claude-todo.md` / §3.9); some may have since been fixed (only arm32
`three-int` retains an xfail today):

- **LLVM — CRITICAL.** A >16-byte struct (`three-int` = 24B) passed by value
  through an **indirect** call (`iface-param` / `funcval-param`) **SIGSEGVs**.
  The *direct* `struct-param/three-int` is fine, so the indirect-call path
  lowers the byval aggregate incorrectly (wrong/missing `byval` on the indirect
  signature). Crashes on every LLVM execution mode (`builder-comp`,
  `-comp-comp`, `-comp-comp-comp`, and — by reasoning, CI-confirmed — the
  `arm32` modes). The VM and the native backends pass `three-int`.
- **aa64** — struct param+return of `three-u32` (non-8-multiple) and `five-u8`
  (sub-word-packed): the trailing field is corrupted. The same defect shows
  through `iface-param` / `funcval-param` (it is the packing, not the call
  shape).
- **x64** — sub-word (`uint16`) multi-return at arity ≥ 3, and struct **param**
  of `three-u32` / `five-u8` (struct-*return* works on x64); likewise visible
  through the indirect call shapes.

The x64 multi-return n=2-cap from the audit (§3.1) is **FIXED** — all-int
multi-return up to arity 5 passes everywhere.

## Planned

More call shapes (handle / `__c_call`) and more aggregate shapes (nested,
larger, managed-field). A 17-byte shape would pin the LLVM crash threshold
exactly (currently bracketed to (16, 24]).
