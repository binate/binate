# addr-aggregate matrix

The **16-byte address-aggregate (2-word) value handling** member of the
conformance matrix family (`../README.md`). Coordinate-addressed:

    conformance/matrix/addr-aggregate/<kind>/<operation>.bn   (+ .expected)

Generated by `conformance/gen-addr-aggregate-matrix.py`.

## Axes & assertion

A managed interface value (`@Iface` = `{data, vtable}`) and a function value
(`@func` = `{vtable, data}`) are 16-byte **2-word** "address aggregates". The
recurring bug class is a backend (especially the bytecode VM) treating one as a
single scalar word at an arg-marshal / return-copy-back / store / extract site —
dropping or swapping a word, so a later dispatch hits a nil/garbage vtable.

- **`<kind>`** — `func-value` (`@func(int) int`) · `iface-value` (`@Box`).
- **`<operation>`** — where the value crosses a boundary before it is invoked:
  `direct` (none) · `copy` (assignment) · `return` (return copy-back) · `arg`
  (arg-marshal) · `return-arg` (returned **then** passed directly) · `field`
  (struct-field store + extract) · `array-elem` (array-element store + index) ·
  `global` (package-level global materialization — the value is stored into a
  package-level cell by `__init`, then read back and invoked; pins the
  materialization / `__init`-store / read-back wiring, not storage sizing).

Assertion: **both words survive every operation** — observed by INVOKING the
value (call the func / call the iface method) after it crosses the boundary. A
dropped or swapped word faults (nil-vtable dispatch) or returns a wrong value.
Every cell expects `42`.

This systematizes a neighborhood with critical failure modes — a VM func value
that is returned and then passed arriving with a nil vtable
(`return-arg`/`func-value`), and a 2-word slice losing its length through a
vtable.

## Current state

No cell carries an `.xfail.<mode>` marker: the 2-word value handling holds across
the grid, and the matrix is regression coverage for it.

## Note

The `field` / `array-elem` cells store an already-**typed** value (bound to a
`var` first), not a bare `func(){}` literal, so they test 2-word survival alone
rather than the inference of a function literal's `@func`/`*func` flavour from the
target type.
