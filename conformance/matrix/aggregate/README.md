# Aggregate matrix

The **value-movement correctness** member of the conformance matrix family
(`../README.md`): does every element / field / scalar survive a given movement
form?  Coordinate-addressed:

    conformance/matrix/aggregate/<form>/<kind>.bn   (+ .expected)

Generated by `conformance/gen-aggregate-matrix.py`.

This fills a gap the sibling matrices left open: `abi/` covers value survival
across a **call boundary** (param / return), `refcount/` the **managed-value
lifecycle**, and `const/` **const** materialization — but none covered plain
(non-managed) **var** assignment, copy, deref-store, and initializer value
correctness.  Two 2026-06-06 codegen defects lived squarely in that gap (see
"Defects this caught" below).

## Axes & assertion

- **form** — the movement under test:
  - `decl-init` — `var a T = <lit>` (baseline);
  - `assign` — `a = <lit>` (composite-literal RHS into an existing var);
  - `copy` — `a = b` (var-to-var);
  - `deref` — `*p = <lit>` through a raw pointer;
  - `global` — a package-level `var g T = <lit>`, read back (the initializer is
    applied by the synthetic per-package `__init`);
  - `field` — store the value into a struct field, read it back (aggregate
    kinds only — a scalar field is just a plain struct field);
  - `param` — pass by value, callee reads every lane;
  - `return` — return by value, caller reads every lane.
- **kind** — `scalar-int` / `scalar-float` / `array-int` / `array-float` /
  `struct-int` / `struct-float`.  The float kinds use non-integer values
  (`1.5`, `2.5`, `3.5`) so the equality check can't pass by accidental integer
  truncation; the three lanes hold distinct values so a swap or partial drop is
  caught.

Assertion: **value correctness**.  Each lane prints
`cast(int, <access> == <literal>)` → `1`, so `.expected` is all `1`s and a
dropped or garbled value prints `0` (or, for the static-emit defects, the cell
fails to compile).  This is the self-checking, target-stable style of the
`scalar-diff` matrix — no dependence on float→int conversion or print
formatting.

## Defects this caught

Validated by reverting the fix (binate `65f79253`) and re-running: 13 cells
fail on the pre-fix compiler, exactly the buggy forms —

- **whole-aggregate `=` assignment silently dropped** — `assign/{array,struct}-
  {int,float}` and `deref/{array,struct}-{int,float}`: a composite-literal RHS
  arrived as an `OP_ALLOC` pointer and the ident/deref store wrote the pointer,
  not the contents.  The `global/{array,struct}-*` cells fail for the same
  reason (the initializer routes through `__init`'s `x = expr`).
- **global float `var` emitting invalid LLVM** (`@g = global double 0`) —
  `global/scalar-float`.

Cells that were already correct pre-fix pass and stand as regression nets:
`decl-init` (a different lowering path), `copy` (a var RHS is a loaded value,
not an alloca), `field` (the selector store arm already loaded the aggregate),
`param`, and `return`.

## Current state

Green on every backend in the default set — `builder-comp`, `builder-comp-int`
(VM), `builder-comp-comp` (gen2) — and on native aa64
(`builder-comp_native_aa64-comp_native_aa64`).  No xfails.
