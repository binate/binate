# dispatch-refcount matrix

Refcount **balance** of a managed multi-return component produced through an
**indirect** call (Code-Red-2 §3.4 — the indirect-producer axis the `refcount`
matrix never crossed). Coordinate-addressed:

    conformance/matrix/dispatch-refcount/<producer>/<component>.bn   (+ .expected)

Generated by `conformance/gen-dispatch-refcount-matrix.py`.

## Axes & assertion

- **`<producer>`** — how the multi-return is produced: `iface-dispatch` (a vtable
  call) or `funcval` (a non-capturing func-value call reading a global — a
  *capturing* closure returning a multi-return is the separate LLVM bug filed in
  `claude-todo.md` CRITICAL).
- **`<component>`** — the managed component destructured out of the tuple:
  `managed-ptr` (`@Counter`), `func-value` (`@func() int`), `iface` (`@Numbered`),
  `managed-slice` (`@[]int`).

The result-side dispatch *value/packing* is covered by `matrix/abi` (the
`MethodResultsFlat` SEAM, `6c39d460`). This matrix asks the *refcount* question
the value-only sweep can't see: does a managed component arrive with exactly one
added ref (Axiom-3) and get released when the destructured alias drops — no leak,
no use-after-free?

**Assertion (balance-invariant):** each cell keeps the managed value alive through
a surviving alias, captures the refcount BEFORE the dispatch, destructures the
component, and asserts `after == before + 1` then `final == before` directly — so
it's robust to the absolute baseline and passes iff the discipline is correct.
Output: `1` (dispatch added one ref), the component's value, `1` (balanced after
drop). Runs on **all** backends — a compile-only or VM-only check would miss a
native refcount divergence (as the abi result-side sweep found for value/packing).

## Current state

**All green on every backend** (LLVM, VM, native aa64/x64) — the managed-component
refcount through both producers (iface-dispatch + funcval) is balanced for
managed-ptr, func-value, iface, and managed-slice components. This **closes the
§3.4 refcount-through-dispatch gap** (previously marked STILL OPEN) and confirms
the discipline; it is now a regression net guarding the SEAM-fixed dispatch path
against a future leak/UAF.

## Notes

- The `func-value` cell drops its alias via a `var`-init (`var drp @func() int =
  …; g = drp`) rather than a bare `g = func(){…}` assignment, which hits the
  separate func-literal-flavour-inference bug (`plan-cr2-followup.md` Plan B).
- The `funcval` producer is a NON-capturing func reading a global; a *capturing*
  closure returning a multi-return is a separate LLVM-codegen bug (silent garbage)
  filed in `claude-todo.md` CRITICAL and pinned by
  `conformance/regressions/capturing-closure-multi-return`. That is why this
  matrix's funcval producer avoids capture.
