# globals matrix

The **package-level global/static storage materialization** member of the
conformance matrix family (`../README.md`). Coordinate-addressed:

    conformance/matrix/globals/<storage>/<type>.bn   (+ .expected)

Generated by `conformance/gen-globals-matrix.py`.

## Axes & assertion

- **`<storage>`** — `init` (package-level `var` with an initializer, run through
  the synthetic `__init`) / `noinit` (zero value) / `readonly` (a `readonly`
  global, overlapping the `readonly` matrix's `field-read` cells).
- **`<type>`** — the type shape of the global: plain & sized scalars, bool,
  float32/64, struct, array, nested-array, managed-slice/ptr, iface-value,
  func-value, and the **named-wrapper** forms (`type X <underlying>`).

**Assertion:** the module COMPILES (no clang *integer constant must have integer
type* / *use of undefined type*) and the global reads back its initialized value
(or zero for `noinit`); one int per lane. Runs on **all** modes incl. native + VM
— the VM materializes globals via a separate data path that must agree.

## Current state

No cell carries an `.xfail.<mode>` marker.

- **`readonly/struct`** — a `readonly` struct global (the `io.EOF` shape) must
  read its fields back, not as 0.
- **named-over-non-struct globals** — `named-{managed-slice,managed-ptr,iface,func}`
  globals need the codegen static-zero dispatch to peel `TYP_NAMED`, or LLVM gets an
  invalid zero token (`global %BnIfaceValue 0`, …). `named-{scalar,float}` reach the
  int else-arm / `IsFloat` peel; a *named struct* (`type S struct{…}`) is
  `TYP_STRUCT`, not a wrapper, so it is a control.
- **named-array / named-managed-slice** — these cells test named-distinct
  transparency: `type X [N]T` parses (grammar D11), `len()`/index peel `TYP_NAMED`,
  and the `named-array` global cell exists (init + noinit). The
  `named-managed-slice` cell reads its real `len(G)` (0 for the noinit nil slice).

The `init/named-array` cell initializes with the *unnamed* `[3]int{...}` literal
(accepted via unnamed→named array assignability), not `Row{...}`.

## Known gaps (not cells here)

- Cross-package globals (the `access` axis) are not yet built — they need
  multi-package directories; the cross-module struct-type-discovery defect
  is pinned by a point-test until then.
