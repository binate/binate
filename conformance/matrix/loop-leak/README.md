# loop-leak matrix

The **per-iteration native-stack-leak** member of the conformance matrix family
(`../README.md`). Coordinate-addressed:

    conformance/matrix/loop-leak/<construct>.bn   (+ .expected)

Generated by `conformance/gen-loop-leak-matrix.py`.

## The class

A construct whose lowering emits an `alloca` (or otherwise grows the native
stack) **inside a loop body** — rather than hoisted to the function entry block
— allocates fresh stack every iteration and never reclaims it (an LLVM `alloca`
in a non-entry block is not freed until the function returns). The program
SIGSEGVs from stack overflow once the loop runs long enough. The output is
*correct right up until the crash*, so an ordinary value-correctness matrix
never sees it — the leak only manifests at scale. Three lowerings bit this way:

- default-init managed aggregate (`var m @[]char`) — `OP_CONST_NIL`
- `var a [N]char = "..."` string→array copy — `OP_RODATA_ARRAY`
- `box()` of a scalar/aggregate register — `OP_BOX`

(see `pkg/binate/codegen/emit_debug.bn`'s alloca-hoist pre-pass and
`claude-todo.md`).

## Axes & assertion

- **`<construct>`** — what sits in the loop body:
  - `const-nil-mslice` / `const-nil-nested-mslice` / `const-nil-funcval` /
    `const-nil-iface` — default-init managed aggregates (`OP_CONST_NIL`).
  - `rodata-array` — `var a [64]char = "..."` (`OP_RODATA_ARRAY`).
  - `alloc-bigstruct` / `alloc-bigarray` — default-init plain struct / array
    (`OP_ALLOC`, always hoisted; **controls** guarding against a regression).
  - `control-make-slice` / `control-string-mslice` — hoisted heap-allocating
    ops; also assert per-iteration **heap** stays bounded (freed each iteration).

- **Assertion** — each cell repeats its construct in a high-iteration loop, then
  prints `42`. A backend that leaks per iteration overflows the stack before the
  print (empty stdout / SIGSEGV) → **FAIL**; a correct backend, and the VM
  (which never touches the native stack for these), prints `42`. Iteration
  counts target ~13 MB of attempted leak — over an 8 MB stack, under a 64 MB
  ceiling — so a leak crashes deterministically while a fixed backend finishes
  in milliseconds (per-iteration work is tiny).

## Complement: the static invariant checker

This matrix is the **end-to-end** half. Its static sibling,
`conformance/check-alloca-hoist.py` (driver `scripts/check-alloca-hoist.sh`),
asserts the underlying invariant — *every `alloca` lives in its function's entry
block* — over the whole corpus, catching the class at compile time for **any**
construct, not just those enumerated here. That checker is what surfaces
`OP_BOX`'s leak (cells 445 / 450), which is awkward to express as a fast runtime
cell (boxing needs a per-iteration heap allocation), so `OP_BOX` is covered
statically rather than as a matrix cell.

Regenerate: `python3 conformance/gen-loop-leak-matrix.py` (idempotent;
coordinate-addressed; never touches `.xfail.<mode>`).
