# Scalar matrix

The **sub-word & 64-on-32 scalar value-correctness** (Class 5) member of the
conformance matrix family (`../README.md`). Coordinate-addressed:

    conformance/matrix/scalar/<op>/<width>/<sign>.bn   (+ .expected)

Generated by `conformance/gen-scalar-matrix.py`.

## Axes & assertion

- **op** — the arithmetic operation (currently `add`, `mul`; planned: `sub`,
  `div`/`rem`, shifts, compares, casts, int↔float).
- **width** — the scalar width in bits (8 / 16 / 32 — sub-word on the 64-bit
  host; 64 planned for the register-pair path on a 32-bit host).
- **sign** — `unsigned` (the confirmed case; `signed` planned).

Assertion: **value correctness** (a refcount-balance check can't see a wrong
value). Each cell computes a sub-word op whose true result OVERFLOWS the width,
then consumes it DIRECTLY with a width-sensitive right shift — no intermediate
sized variable, which would re-narrow it. A backend that narrows sub-word
results to their width (LLVM) yields the correct value; one that leaves dirty
upper bits in the host register (the bytecode VM and the native backends —
plan-code-red.md §3.8) diverges. The `.expected` is the correct (narrowed)
value, computed at full precision by the generator.

## Current state

The dirty-upper-bits defect is CONFIRMED: every cell PASSES in the LLVM modes
(`builder-comp`, `-comp-comp`, `-comp-comp-comp`) and is xfailed in the VM
modes (`-int`, `-int-int`, `-comp-comp-int`), where `execArithOp` computes at
the host width without narrowing. The native lanes (not in the default mode
set) are expected to fail likewise — add their xfails when those lanes run.
See `claude-todo.md` and plan-code-red.md §3.8.
